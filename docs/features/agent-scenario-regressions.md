# Agent scenario regression pack

This is a repeatable quality suite for realistic work a user may delegate to the agent. It turns the Flappy Bird request that exposed a missing completion-evidence report into a tracked regression case, then covers common coding, document, data, research, and browser tasks. The cases are prompts and acceptance criteria, not claims that the current agent supports every task or has passed them.

## How to run a case

1. Use a fresh, isolated synthetic workspace or supplied fixture for each run. Record the case ID, app build, model, permission mode, and run link in the test run record. Do not use real customer accounts, credentials, or private data.
2. Submit the prompt verbatim. Review the proposed plan and checks; approve only the tools and access needed for that case. Use explicit named public hosts and enable Named public websites only for research cases that require it.
3. Let the agent finish. Check the actual output with the case's acceptance criteria and applicable project validator, build, tests, or browser interaction. A generated file existing is not by itself proof that it works.
4. If a check fails, keep the case open, capture a minimal reproduction and the failing evidence, fix the agent/product defect or the generated deliverable as appropriate, add a regression check when possible, then rerun the same case from a clean fixture. Do not change the expected result merely to make a failure pass.
5. Mark a case **Done / Passed** only when every acceptance item is verified and the agent reports evidence for every approved check. Use **Fix required**, **Blocked**, or **Not run** otherwise. A safe refusal or clarification can pass cases whose expected behavior is to refuse or clarify.

The completion report contract is `[CHECK N: PASS]` or `[CHECK N: INCOMPLETE]` for every approved success check, with concrete evidence. Missing, ambiguous, or unsupported evidence is incomplete, not done. For code tasks, use workspace-scoped project validation; when Full Access is required to execute project build/test scripts, the test operator must review the approved plan and generated scripts first. Static validation alone does not prove browser behavior. Keep secrets and private content out of run notes and telemetry.
