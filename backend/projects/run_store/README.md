# Run store service

Owns durable run metadata, payload-bound tool approvals, ordered event persistence, replay queries, status transitions, cancellation requests, stale-run recovery, and completed-event lookup. The current adapter persists to the local SQLite database shared with prompt-free telemetry.

- Entry point: `app:app`
- Local port: `8773`
- Routes: `GET /health` (reports `store`, a fingerprint of the database file, so the gateway can detect a run store that keeps runs elsewhere); authenticated run creation, event append/replay, conversation listing, delegate execution claim, cancel request, approval create/resolve/expire, incomplete-run recovery, finish, done-event lookup, and research-collection reads/writes.
- Lifecycle: cancellation records a durable request and moves a live run to `cancelling`; finishing maps it to `cancelled` or `timed_out`. Disconnects and abandoned `running` rows become `interrupted`. Terminal statuses reject late activity events.
- Delegate execution: `delegation_scheduler.py` admits only DAG-ready subtasks, enforces a concurrency limit, and cancels active callbacks on parent cancellation or service errors. Unless a caller supplies a limit, `run_subtask_plan` reads `POCKPOCK_MAX_DELEGATE_CONCURRENCY` (default `3`, allowed `1`–`16`). Child run IDs are deterministic per parent/subtask; an atomic execution claim prevents duplicate gateway dispatch, while retries load the existing durable child and its events rather than restarting it. Child execution applies the approved context/tool contract and deadline; cancellation, timeout, and operational failures remain typed non-success results. Child-created files remain isolated until a parent reviews and approves the exact diff; stale path/hash checks, baseline-relative validation, safe rollback, and durable parent artifact events protect the merge.
- Delegation contract: a child run is bound to an active parent and its latest approved plan, including the exact approved purpose/expected-result prompt, role, tools, dependency set, and permission ceiling. Its context builder exposes only those instructions and explicitly approved dependency results; arbitrary parent or sibling context is not passed through. Children must use isolated workspaces, and edits remain subject to the existing staged-patch validation and conflict checks. Artifact access is denied until artifacts can be explicitly assigned in an approved plan. The store allows at most 16 direct children and three delegation levels. A `delegate_result` event uses contract version 1 and a typed status, summary, evidence, artifact IDs, and incomplete checks. Parent/child metadata and ordered event history are replayed after restart.
- Migration: startup adds cancellation and delegation fields to existing `agent_runs` tables without rebuilding or discarding run history. Existing rows remain root runs with no delegation metadata.
- Research collections: task/workspace-scoped source records and user notes are stored separately from event payloads. Each explicit save/refresh stores at most 200 KB of extracted UTF-8 text per changed snapshot with a content hash and capture timestamp. All versions remain until collection deletion; no background refresh is performed.
- Retention: delegation metadata and result events follow the same local run-history retention and access boundary as other run records; no separate child-context store is introduced by this contract milestone.
- Configuration: `POCKPOCK_INTERNAL_TOKEN`, `POCKPOCK_RUN_STORE_INTERNAL=1` prevents the service from proxying its own persistence calls.
- Security: bind to `127.0.0.1`; non-health requests require `X-PockPock-Internal-Token`.
- Run from this folder with the repository environment: `..\..\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8773`.

Install the service dependencies listed in `requirements.txt` into the shared repository environment. The service imports the shared repository in `backend/scripts/agent_run_store.py` and `backend/scripts/observability_dashboard.py`, plus `backend/projects/internal_auth.py`.
